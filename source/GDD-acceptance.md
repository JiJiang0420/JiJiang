# 《魔女的盛宴 2.0》GDD 0.2 验收单

对应文档：[GDD 0.2 · 整合验收稿](GDD.md)。当前状态：**全部待用户验收**。

本次验收对象是游戏设计与首版范围。通过后进入工序分工与制作任务单评审；工序分工及启动范围经用户确认后开始开发。后续用户另行授权垂直切片开发；部分机制验证已经执行，结果见[切片状态](docs/vertical-slice-status.md)。本表保留设计验收用途，不把自动测试通过视为用户已验收。

## 一、已确认方向核对

GDD 应始终保留以下用户要求，后续修订不得无记录改变：

- PC、3D、可旋转视角、类幸存者战斗。
- 一个玩家身体、三件古神斗篷、战场切换与权能组合。
- 手动绘制为主要攻击方式，三件斗篷都能独立处理普通敌人。
- 局外成长；采用三位古神设定，“魔女”另行解释。
- 先设计、再分工，经用户检查验收后开发。

## 四、参数与功能验证的边界

GDD 中生命、伤害、冷却、距离、八分钟时长、货币价格和同屏敌量都是首轮参数。设计验收确定规则与试验基线；开发后按试玩结果调整，保留变更原因。

| 项目 | 本轮完成的文档工作 | 开发后需要的证据 |
| --- | --- | --- |
| 三斗篷独立战斗 | 定义有效攻击及普通敌人生命，给出两次施法击杀基线 | 六个孤敌/小群场景实际通过 |
| 组合与连锁 | 定义三组互动、方向、来源和触发上限 | 操作复现、异常输入与重复触发验证 |
| 经济 | 给出固定收入与击杀上限两条收支样例 | 商店、扣款、效果、结算与保存一致 |
| 视听 | 明确三斗篷的轮廓、纹样、动态和反馈优先级 | 正常战斗镜头辨识与预警检查 |
| 性能 | 给出候选参考机、帧时间目标和测试场景 | 对应实机的记录；无实机则该项未验证 |
| 存档 | 定义永久保存、不续局及异常处理 | 重启、保存失败、备份恢复和重复奖励测试 |

## v0.2 追加试玩验收

- 未读说明时，能否根据范围圈、攻击带和命中圈判断攻击位置？
- 能否区分挥空、命中、破甲、打断与改向？
- 开场是否仍然需要等待，成组敌人与早期疯仆是否产生走位选择？
- Q试用短切、收线、推墙后，能否分别说出操作变化和代价？
- 第一店选分支、后两店选配套后，攻击方式是否真的变化？
- 不把自动测试通过作为“好玩”的验收结果；记录仍然无聊或费力的具体时刻。
