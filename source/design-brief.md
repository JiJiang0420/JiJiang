历史文档：[用户原稿 V1.0](three-cloaks-source-v1.0.md) · [评审与补充 V1.1](three-cloaks-review-v1.1.md)。原稿保留原样；本页用于导航与记录流程，完整规则以当前待验收 GDD 为准，尚未通过的新增方案不视为用户已确认。

## 已确认的目标与顺序

- 项目名称：《魔女的盛宴 2.0》。
- 跳过 1.0 的旧设计，直接以 2.0 的新设计为起点。
- 先完成初步设计，再制定各工序的分工、交付物与验收标准。
- 由用户检查并验收设计及分工方案后，开始游戏开发与正式资产制作。
- 制作流程需要覆盖游戏搭建、素材绘制、游戏建模、特效、动画及策划案迭代；具体需求由最终设计决定。
- 工具由助手提出选择与使用方案，用户提及的 kirita 暂按 Krita 理解。

## 已确认的游戏方向

- 类型：类幸存者战斗。
- 平台与画面：PC，3D，可旋转视角。
- 玩家操控一个身体，使用三位古神的斗篷所蕴含的力量。用户已选择采用初稿的古神设定，“魔女”的身份另作解释。
- 玩家在战场中切换三件斗篷，通过不同权能的配合进行战斗。
- 以手动绘制为主要攻击方式；三种魔法都应能独立处理普通敌人。
- 三件斗篷均可在局外强化。
- 初稿以绯月的断裂、星汐的流转、圣棘的界定为核心；完整 GDD 已补充操作、战斗、成长、经济、视听、保存和样件范围，具体修订待用户确认。
- 当前仓库未发现初稿中提到的 V0.1 Godot 工程，记录为外部工程待提供与核对；不视为已有实现。

## 初步工具方案

| 工具 | 用途 | 使用约定 |
| --- | --- | --- |
| Godot 4 稳定版 + GDScript | 3D 场景、游戏逻辑、交互、UI、音频整合与 PC 构建 | 确定目标硬件和渲染需求后固定具体版本与渲染器 |
| Krita | 概念稿、角色立绘、贴图、图标及需要的逐帧动画 | 保留分层 `.kra` 源文件，按引擎需求导出 PNG 或图集 |
| Blender | 角色与场景建模、UV、绑定、骨骼动画 | 保留 `.blend` 源文件；实时 3D 资产优先通过 glTF/GLB 导入 Godot |
| Godot 粒子、Shader 与 AnimationPlayer | 游戏内特效、镜头及事件动画 | 在实际游戏场景中验证效果、时序和性能 |
| Markdown + Git | 策划、资产规范、任务、决策与验收记录 | 每次修订记录原因、影响及用户验收状态 |
| Audacity（按需） | 音效剪辑、降噪及音量整理 | 保留原始音频与编辑工程，按引擎用途导出 |

上述保留初始工具方案。垂直切片实际采用 Godot 4.6.3、Blender 4.3.2 及 Python 程序素材；已创建游戏工程。Krita 与正式骨骼动画尚未进入本切片生产。

## 初稿评审重点

以下项目已完成文档评审并整合到 GDD，附样件的验收方案；当前实际执行结果单列于切片状态：

1. 三件斗篷的战斗定位、操作差异与权能配合；切换是否产生有意义的选择。
2. 切换条件、冷却、资源，以及离场斗篷的效果持续规则；是否出现无脑轮换或长期只用一件的最优解。
3. 移动、攻击、瞄准、镜头旋转与切换的操作负担；敌群、攻击预警和特效的可读性。
4. 单局目标、成长、敌人节奏、结束条件与奖励，以及局外强化对难度和构筑选择的影响。
5. 首个可玩版本的内容范围、3D 资产成本与大量敌人同屏时的性能目标。

评审时区分用户已确认内容、设计矛盾或缺项、可选改进方案，并说明建议原因及对其他系统的影响。

## 初步设计的交付内容

依据初稿继续讨论、完善并验收以下内容：

- 一句话定位、目标玩家与核心体验。
- 世界观边界、主角身份与游戏目标。
- 一轮核心玩法的步骤、反馈、成功和失败条件。
- 主要系统之间的关系，以及首个可玩版本的内容范围。
- 一段约 5–10 分钟的代表性游玩流程；长度随玩法调整。
- 画面、镜头、UI、动画、特效和声音的方向。
- 优先验证的问题、暂缓内容和验收方法。

## 初步设计之后的分工方案

在初步设计获得认可后，为每个工序列出负责人或执行角色、输入资料、交付物、依赖、工具、验收标准和返修流程。工序至少评估策划、程序、2D 美术、3D 建模、动画、特效、音频、整合与测试。

正式制作前约定资产尺寸或模型单位、坐标方向、命名、动画片段、透明通道、导出格式及目录。用一个代表性资产验证源文件到 Godot 的导入流程后，再批量制作。
